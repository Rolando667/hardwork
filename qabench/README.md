# QABench — стенд тестування LLM-промтів для QA-аудиту діалогів колцентру

Десктопний застосунок для Windows, який проганяє один промт (системну інструкцію)
через безліч комбінацій **модель × рівень роздумів × діалог × повтор**, викликає
API провайдерів (Anthropic, Google Gemini, OpenAI) і показує зведену таблицю
вердиктів, збігів з еталоном, токенів, вартості та часу.

Інтерфейс — українською. Темна тема, масштабоване вікно, таблиці з сортуванням
за кліком по заголовку.

---

## Можливості

- **Моделі** — довільна кількість моделей трьох провайдерів, кожна зі своїм
  API-ключем (маскується), цінами $/1M токенів (редаговані), типом параметра
  роздумів, `max tokens` і температурою.
- **Промти** — редактор із лічильником символів і приблизних токенів (символи/2.7).
- **Діалоги** — транскрипти з необов'язковим полем «Еталон». Імпорт вставкою
  тексту або завантаженням `.txt` файлів пачкою (назва = ім'я файлу).
- **Запуск** — мультивибір моделей/рівнів/діалогів, вибір одного промта, 1–5
  повторів, 1–4 паралельних запити, попередній підрахунок викликів (попередження
  якщо > 200), прогрес-бар, коректне скасування, лог помилок.
- **Результати** — зведена таблиця (рядки — діалоги, колонки — «модель @ рівень»)
  з іконками вердиктів, дрібними метриками, tooltip (коментар + сира відповідь),
  підсвіткою збігу/розбіжності з еталоном, мажоритарним вердиктом і позначкою
  нестабільності при повторах. Підсумки по колонках і загальна вартість.
- **Експорт** — CSV, XLSX; автозбереження прогону в JSON після завершення +
  ручне збереження і відкриття збережених прогонів.

## Абстракція рівнів роздумів

Користувач обирає універсальний рівень: **none / minimal / low / medium / high**.
Перед викликом рівень транслюється у параметр провайдера згідно з типом,
указаним у моделі. Увесь мапінг зберігається в редагованому файлі
`reasoning_map.json` (меню **Налаштування → Мапінг роздумів**), тож числа можна
правити без зміни коду. У tooltip клітинки показано, у що саме транслювався рівень.

| Тип параметра                 | Куди транслюється                                              |
|-------------------------------|---------------------------------------------------------------|
| `anthropic_thinking_budget`   | `thinking.budget_tokens` (Claude 4.5 і старіші)               |
| `anthropic_adaptive_effort`   | `thinking.type=adaptive` + `output_config.effort` (Claude 4.6+) |
| `gemini_thinking_budget`      | `generationConfig.thinkingConfig.thinkingBudget` (Gemini 2.5) |
| `gemini_thinking_level`       | `generationConfig.thinkingConfig.thinkingLevel` (Gemini 3+)   |
| `openai_reasoning_effort`     | `reasoning_effort`                                            |

Застосунок автоматично дотримується обмежень провайдерів (напр. для Anthropic
піднімає `max_tokens` вище за `budget_tokens`; для Gemini не передає одночасно
`thinkingBudget` і `thinkingLevel`).

## Зберігання даних

Усі дані зберігаються у `%APPDATA%\QABench\`:

```
%APPDATA%\QABench\
  config.json          # моделі з ключами, проксі, останні вибори
  reasoning_map.json   # мапінг рівнів роздумів
  prompts\*.txt        # промти
  dialogs\*.json       # діалоги (назва, текст, еталон)
  results\*.json       # збережені прогони (конфігурація + сирі відповіді + час)
```

Меню **Дані → Відкрити папку даних** відкриває цю теку в Провіднику.
Проксі (**Налаштування → Проксі**) застосовується до всіх запитів.

## Запуск із вихідного коду

Потрібен **Python 3.11+**.

```bat
python -m pip install -r requirements.txt
python main.py
```

## Збірка в один .exe

1. Встановіть Python 3.11+ з [python.org](https://www.python.org/downloads/)
   (під час встановлення позначте **Add Python to PATH**).
2. У теці проєкту запустіть:

   ```bat
   build.bat
   ```

   Скрипт встановить залежності та збере застосунок за допомогою PyInstaller:

   ```
   pyinstaller --onefile --noconsole --name QABench --collect-all PySide6 main.py
   ```

3. Готовий файл — `dist\QABench.exe`. Він працює на чистому Windows 10/11
   **без встановленого Python**. Дані створюються у `%APPDATA%\QABench\`
   при першому запуску.

## Критерії приймання

1. Додаєте модель Anthropic і модель Google з ключами → обидві доступні на
   вкладці «Запуск».
2. Обираєте 1 промт, 3 діалоги (один з еталоном «Не відповідає стандарту»),
   2 моделі, рівні `low`+`medium`, повторів 1 → Старт → прогрес іде, наприкінці
   таблиця 3×4 заповнена, клітинки з еталоном підсвічені зеленим/червоним.
3. Обрив інтернету посеред прогону не валить застосунок: проблемні клітинки
   позначені ⚠️, решта дорахувалась.
4. Експорт XLSX відкривається в Excel і містить вердикти, коментарі, токени,
   вартість, підсумкові рядки.
5. Після перезапуску моделі, промти, діалоги і збережені прогони на місці.

## Виклики API

- **Anthropic** — `POST https://api.anthropic.com/v1/messages`, заголовки
  `x-api-key` та `anthropic-version: 2023-06-01`; `system` = промт, `messages`
  = транскрипт. Структурований вихід забезпечується інструкцією у промті; парсер
  зрізає обгортки ```` ```json ````.
- **Google Gemini** — `POST .../v1beta/models/{model}:generateContent?key=...`;
  `systemInstruction` = промт, `contents` = транскрипт;
  `generationConfig.responseMimeType = "application/json"` + `responseSchema`
  (enum статусу) для чистого JSON.
- **OpenAI** — `POST https://api.openai.com/v1/chat/completions`;
  `response_format` типу `json_schema` з тим самим enum.

Таймаут 120 с на запит; до 2 ретраїв на 429/5xx з експоненційною паузою;
будь-яка помилка → текст помилки в клітинці, прогін продовжується.

> Примітка: якщо якась деталь актуального API провайдера зміниться, відповідні
> числа роздумів правляться у `reasoning_map.json`, а решта параметрів — у
> модулях `providers/`.
